# Common Data Types and Interfaces

This document outlines the key data structures and interfaces used throughout the Time Ruler plugin, primarily defined in `src/types/index.d.ts`, `src/main.ts`, and `src/types/enums.ts`.

## Plugin Settings

### `TimeRulerSettings`

Defined in `src/main.ts`, this type specifies the structure for all settings managed by the Time Ruler plugin.

```typescript
type TimeRulerSettings = {
  calendars: string[]; // Array of iCalendar URLs
  fieldFormat: FieldFormat['main']; // Preferred format for task metadata (dataview, tasks, etc.)
  muted: boolean; // Whether sound effects are muted
  timerEvent: 'notification' | 'sound'; // Event type when a timer completes
  inbox: string | null; // Path to a default inbox note for new tasks
  search: string; // Custom Dataview query for filtering pages
  taskSearch: string; // Text filter for tasks
  fileOrder: string[]; // User-defined order of files in the view
  customStatus: { // Configuration for custom task statuses
    include: boolean; // True to include specified statuses, false to exclude
    statuses: string; // String of status characters (e.g., "-/?!")
  };
  showCompleted: boolean; // Whether to display completed tasks
  dayStartEnd: [number, number]; // Start and end hours for the timeline view (e.g., [0, 24])
  groupBy: false | 'priority' | 'path' | 'hybrid' | 'tags'; // How tasks are grouped
  twentyFourHourFormat: boolean; // Whether to use 24-hour time format
  filterFunction: string; // Custom JavaScript function for filtering tasks
  addTaskToEnd: boolean; // Whether to add new tasks to the end of a file/section
  extendBlocks: boolean; // Whether to extend time blocks to the next block
  hideTimes: boolean; // Whether to hide times on tasks in the view
  borders: boolean; // Whether to show borders around day/time blocks
  viewMode: 'hour' | 'day' | 'week'; // Current view mode for the timeline
  scheduledSubtasks: boolean; // Whether to show unscheduled subtasks under their parent
  openInMain: boolean; // Whether to open Time Ruler in the main pane by default
};
```

## Core Data Structures

### `TaskProps`

This is the central interface representing a task within the Time Ruler plugin. Defined in `src/types/index.d.ts`.

```typescript
type TaskProps = {
  type: 'task'; // Discriminator for type guards
  id: string; // Unique identifier (e.g., filePath::lineNumber or filePath for page tasks)
  page: boolean; // True if the task is represented by a whole page, false if it's an item in a list
  title: string; // Cleaned title for display (wikilinks processed)
  originalTitle: string; // Title as it appears in the Markdown, before processing
  originalText: string; // The full original Markdown text of the task line
  notes?: string; // Content from subsequent lines indented under the task
  tags: string[]; // Array of tags (e.g., "#tag")
  children: string[]; // Array of child task IDs
  position: STask['position']; // From Dataview: start and end line/col/offset in the file
  path: string; // Full path to the file containing the task, may include #heading
  parent?: string; // ID of the parent task, if it's a subtask
  extraFields?: Record<string, string>; // Custom fields extracted from Dataview inline syntax (e.g., [key:: value])
  duration?: { hour: number; minute: number }; // Task duration
  status: string; // Single character representing task status (e.g., ' ', 'x', '/', '>')
  blockReference?: string; // Obsidian block reference (e.g., ^blockid) if present at the end of the task line
  fieldFormat: FieldFormat['main']; // The detected primary metadata format for this task
  completed: boolean; // True if the task is marked as completed
  query?: string; // Dataview query string if this task generates children from a query
  queryParent?: string; // ID of the task that this task is a query result of
  queryChildren?: string[]; // IDs of tasks generated by this task's query
  links: string[]; // Array of outgoing links from the task text

  // Obsidian Reminder plugin format
  reminder?: string; // Reminder date/time string (e.g., "YYYY-MM-DD HH:MM")

  // TASKS plugin-style fields (can also be parsed from other formats)
  created?: string; // ISO date or datetime string
  start?: string; // ISO date or datetime string (start date)
  scheduled?: string; // ISO date or datetime string (scheduled date)
  priority: number; // Numeric representation of priority (see TaskPriorities enum)
  due?: string; // ISO date or datetime string (due date)
  completion?: string; // ISO date or datetime string (completion date)
  repeat?: string; // Recurrence rule string (e.g., "every day")
};
```

type EventProps = {

## Drag and Drop Types

Defined in `src/types/index.d.ts`.

### `DragData`

A discriminated union representing the data associated with an item being dragged. The `dragType` property determines the specific shape.

```typescript
type DragData =
  | ({ dragType: 'group' } & GroupComponentProps) // When dragging a whole group of tasks
  | ({ dragType: 'task' } & TaskComponentProps)  // When dragging a single task
  | ({ dragType: 'block' } & BlockComponentProps) // When dragging a block of tasks/events
  | ({ dragType: 'task-length' } & { // When dragging to adjust a task's duration
      id: string; // Task ID
      start: string; // Task's scheduled start ISO
      end?: string; // Current end ISO being dragged to
    })
  | ({ dragType: 'time' } & { // When dragging from an empty time slot to create a new task/block
      start: string; // Start ISO of the drag
      end?: string; // Current end ISO being dragged to
    })
  | ({ dragType: 'due' } & { task: TaskProps }) // When dragging a task's due date handle
  | { dragType: 'new_button' }; // When dragging the "new task" button
```
*Note: `GroupComponentProps`, `TaskComponentProps`, and `BlockComponentProps` are component prop types that typically include underlying data like `TaskProps[]` or `TaskProps`.*

### `DropData`

Represents data associated with a droppable area, indicating what action might be taken or what properties might be applied if `DragData` is dropped there.

```typescript
type DropData =
  | Partial<TaskProps> // Often used for scheduling: e.g., { scheduled: "YYYY-MM-DDTHH:MM" }
  | { type: 'heading'; heading: string } // Dropping onto a group heading (for reordering)
  | { type: 'delete' } // Dropping onto a delete zone
  | { type: 'move' }; // Dropping onto a "move task" zone
```

### Priority Mappings (Assumed from `src/types/enums.ts`)

*   **`priorityKeyToNumber: Record<string, TaskPriorities>`**: Maps string keys (e.g., "highest") to `TaskPriorities` numbers.
*   **`simplePriorityToNumber: Record<string, TaskPriorities>`**: Maps simple text symbols (e.g., "!!!", "!!", "!") to `TaskPriorities` numbers.
*   **`priorityNumberToSimplePriority: Record<TaskPriorities, string>`**: Inverse of `simplePriorityToNumber`.
*   **`priorityNumberToKey: Record<TaskPriorities, string>`**: Inverse of `priorityKeyToNumber`.

### Tasks Plugin Emoji Mappings (Assumed from `src/types/enums.ts`)

*   **`keyToTasksEmoji: Record<string, string>`**: Maps metadata keys (e.g., "scheduled", "due", "priority_high") to their corresponding "Tasks" plugin style emojis (e.g., "⏳", "📅", "⏫").
*   **`TasksEmojiToKey: Record<string, string>`**: Inverse of `keyToTasksEmoji`.

### `RESERVED_FIELDS: string[]` (Assumed from `src/types/enums.ts`)

An array of strings listing field names that are considered reserved and should not be treated as generic `extraFields`.

### `isTaskProps(data: DropData): data is Partial<TaskProps>` (Assumed from `src/types/enums.ts`)

## Obsidian Interface Extensions

The `src/types/index.d.ts` file also extends some global Obsidian interfaces:

```typescript
declare module 'obsidian' {
  interface App {
    isMobile: boolean; // Adds isMobile property to App
  }

  interface Vault {
    getConfig: (key: string) => string | string[] | undefined; // For userIgnoreFilters, etc.
    readConfigJson: (
      path: string
    ) => Promise<Record<string, string | number | boolean>>; // For daily-notes config
  }
}
```

These types and interfaces form the backbone of data handling and state management within the Time Ruler plugin, ensuring consistency and type safety across different modules and functionalities.
